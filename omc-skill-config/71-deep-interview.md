### scope 고정 (MANDATORY)

이번 작업 범위를 벗어나는(Out of Scope) 주제는 질문 대상에서 배제하여 Scope Creep을 방지한다.

**scope 기준**: Round 0에서 잠근 topology의 **active components**. deferred components는 scope 밖.

- deferred 컴포넌트는 ambiguity 점수 계산 대상에서 **제외**하고 질문을 생성하지 않는다 (SKILL.md의 active-only 채점 동작을 명문화).
- active 컴포넌트 내부의 모호성만 ambiguityThreshold(0.01)까지 파고든다.
- 인터뷰 도중 scope 밖 주제가 필요해 보이면 질문하지 말고 `state.topology.deferrals`에 추가 기록만 한다.
- **AI 자의로 deferred → active 승격 금지.** 사용자 명시 요청 시에만 Round 0 게이트를 재실행하여 topology를 재잠금한다. (SKILL.md의 "Round 0 exactly once"는 사용자 명시 승격 요청 시 재실행 허용으로 **오버라이드**한다 — 본 config가 SKILL.md에 우선)
- 해결책 방향을 물을 때는 **원본 코드 최대한 보존 + 가장 간단하고 단순하지만 충분히 효과 좋은 안**을 기본 선택지로 먼저 제시한다.

**MANDATORY — Round 0 잠금 직후 자체 검증 체크리스트 출력**:
- [ ] active components: __________
- [ ] deferred components: __________
- [ ] 두 목록이 사용자 확인을 거쳤는가? (AI 단독 확정 금지)
- [ ] 이후 질문은 active에서만 생성됨을 확인했는가?

**MANDATORY — 매 라운드 질문 생성 직전 자체 검증 체크리스트 출력**:
- [ ] 이번 질문의 대상 컴포넌트: __________ (active 목록에 있는가?)
- [ ] deferred 대상 질문 0건인가? (1건이라도 있으면 질문 폐기 후 재생성)
- [ ] 질문이 active 경계를 넘어 새 주제를 끌어들이지 않는가?

**MANDATORY — 승격 요청 발생 시 자체 검증 체크리스트 출력**:
- [ ] 승격 요청 주체: [사용자 명시 요청 / AI 판단]
- [ ] AI 판단 → 승격 금지. deferrals 기록만 하고 계속 진행
- [ ] 사용자 명시 요청 → Round 0 게이트 재실행 후 재잠금했는가?
- [ ] 재잠금 후 active/deferred 목록을 다시 출력했는가?

**잘못된 진행 금지 (anti-patterns, MANDATORY)**:
- ❌ deferred 컴포넌트에 "확인차" 질문 → 승격과 동일. 금지.
- ❌ active 질문에 scope 밖 주제 끼워넣기 ("rate limit 정책은? 그리고 OAuth 계획도 있나요?")
- ❌ ambiguity 점수가 안 떨어진다는 이유로 deferred를 active로 승격
- ❌ Round 0 없이 인터뷰 시작 → scope 기준 부재. Round 0 게이트 필수.

### 인터뷰 질문 방식 (MANDATORY — SKILL.md Step 2b 오버라이드)

인터뷰 라운드 질문(Step 2b)에 **AskUserQuestion 도구를 사용하지 않는다.**
질문은 일반 대화 텍스트로 출력하고, 사용자의 자유 텍스트 답변을 받는다.

- 라운드 헤더(`Round {n} | Component | Targeting | Why now | Ambiguity {score}%`)는 텍스트로 유지한다.
- SKILL.md Interaction 섹션의 "Use AskUserQuestion for each interview question" 규칙은 본 조항으로 **오버라이드**한다 (본 config가 SKILL.md에 우선).
- 질문 방식 전역 규칙(`00-overrides.md` "질문 방식 — 전역")이 본 조항을 클로드 전체로 일반화했다. 3단 구조의 canonical 정의는 본 파일이 유지한다.
- **예외**: Phase 5 Execution Bridge(실행 방식 승인)는 기존대로 AskUserQuestion을 유지한다. 실행 게이트이므로 명시적 선택이 안전장치다.

**질문 출력 3단 구조 (MANDATORY — 설명 먼저, 질문 나중):**

매 질문은 반드시 아래 3단 구조로 출력한다:

1. **배경 설명**: 왜 이걸 묻는지, 관련 개념이 뭔지 **최대한 간단하고 쉽게** 설명한다. 전문용어는 반드시 풀어서 쓴다.
2. **구체 예시**: 답이 갈리는 상황을 보여주는 실제 예시를 1개 이상 포함한다. 선택지에 따라 결과가 어떻게 달라지는지 드러나야 한다.
3. **질문 + 참고 선택지**: 질문을 던지고, 참고용 선택지를 번호 목록으로 나열한다. 마지막에 "번호로 답해도 되고, 자유롭게 설명해도 된다"를 안내한다.

**출력 예시:**

```
Round 3 | Component: 알림 서비스 | Targeting: Constraint Clarity | Ambiguity: 12%

**왜 묻는지**: 알림 발송은 네트워크 문제 등으로 실패할 수 있는데,
실패했을 때 어떻게 할지에 따라 코드 구조가 크게 달라집니다.

**예시**: 사용자 100명에게 알림을 보내다 3명이 실패했다고 해봅시다.
- 그냥 포기하면 → 코드는 단순하지만 3명은 알림을 못 받음
- 재시도하면 → 대부분 복구되지만 재시도 로직이 추가됨
- 실패 큐에 쌓으면 → 유실은 없지만 큐 관리 인프라가 필요함

**질문**: 알림 발송 실패는 어떻게 처리할까요?
1. 재시도 3회 후 포기 (가장 단순)
2. 실패 큐에 쌓고 배치 재처리
3. 실패 시 관리자에게만 별도 알림

번호로 답하셔도 되고, 다른 방식을 자유롭게 설명하셔도 됩니다.
```

**anti-patterns (MANDATORY):**
- ❌ 설명 없이 질문만 던지기 ("알림 실패 처리는 어떻게 할까요?" 한 줄)
- ❌ 예시 없이 추상적 설명만 하기
- ❌ 설명이 길다는 이유로 AskUserQuestion 박스로 회귀
- ❌ 전문용어를 풀이 없이 사용 (예: "idempotent하게 처리할까요?" ❌ → "같은 알림이 두 번 가도 문제없게 만들까요?" ⭕)
- ❌ 사용자 답변 없이 라운드의 방향·선택을 자의 확정하고 다음 라운드로 진행 (2026-08-19 STAT-586 실위반: 라운드 1 자의 확정 → 사용자 롤백 지시 "너마음대로 확정하지말고" 로 라운드 재실행)
- ❌ 재설명 요청에 직전과 같은 추상 수준으로 표현만 바꿔 답하기 → 아래 「재설명 요청 대응 형식」 절

### 재설명 요청 대응 형식 (MANDATORY — 2026-08-20 신설)

사용자가 직전 설명에 재설명을 요청하면("다시 설명해줘", "이해 못 했어", "쉽게", "예시 포함해서" 류) 다음 3항으로 답한다. 위 「질문 출력 3단 구조」가 **최초 질문**의 형식이라면, 본 절은 **그 설명이 실패했을 때**의 형식이다.

1. **실데이터 예시 의무**: 실제 관측 자료(데이터 카탈로그 MD·실측 엑셀/HAR·로컬 DB 실값)에서 **그 계정·그 파일·그 시트/행·실제 값**을 짚는다. 추상 예시("어떤 값이 있다고 하자") 금지. 실물 위치를 모르면 먼저 찾아 열고 나서 답한다.
2. **용어 미니 풀이표**: 직전 답변에 쓴 도메인 용어·축약어를 2열 표(용어 | 뜻)로 풀어 설명 앞에 붙인다.
3. **동일 추상 수준 반복 금지**: 직전 설명과 같은 층위를 표현만 바꿔 반복하면 재설명이 아니다 — 반드시 한 층 아래(실물·실값)로 내려간다. **같은 주제 두 번째 재설명 요청부터는 실물 열람(해당 파일 Read/실측)이 선행 의무다.**

- 본 절은 `50-critic.md` 「도메인 SSOT 경로 주입」의 인터뷰 출력 버전이다 — 리뷰어에게 요구하는 "SSOT 를 읽고 인용하라"를 오케스트레이터 자신의 설명 출력에도 적용한다.
- (2026-08-19 STAT-586 인터뷰 실사고: "예시 포함해서 쉽게 다시" 요청 7회+ 반복. M3/M6 시트를 개념으로만 반복 설명해 사용자가 "어떤 계정의 어떤 엑셀인지"를 세 번 되묻고 **직접 엑셀을 연 뒤에야** 이해 — 실계정·실파일·실값을 처음부터 짚었으면 왕복 1회로 끝났다. 이 반복 왕복이 인터뷰 실작업 ~2h 중 ~30분.)
